# Android open testing workflow

Use this module when `open-testing` is selected in the `testing` category. Read it with global rules and only other selected workflows that affect the task.

## Use when

A candidate is ready for broad or opt-in tester access and the team can respond to wider feedback.

## Avoid when

Invite-only testing is still needed or the candidate/support readiness is insufficient.

## Agent procedure

1. Confirm broad access matches product risk and support capacity.
2. Define crash/feedback triage and rollout blockers.
3. Review privacy, account creation, and support paths.
4. Define pause/recovery criteria and verify current console rules.

## Completion checks

- [ ] Audience and access are understood.
- [ ] Monitoring and triage have an owner.
- [ ] Open testing is described as distribution, not an automation level.
