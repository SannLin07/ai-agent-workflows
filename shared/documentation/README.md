# Documentation rules

- Put a rule in one canonical file and link to it from other workflows.
- Keep an entrypoint focused on decisions and actions; move branch-specific reference into a nearby document only when that makes the entrypoint materially easier to follow.
- Distinguish confirmed behavior from assumptions, recommendations, and unresolved questions.
- Include an owner or review trigger for facts that change, such as package versions, platform requirements, and deployment steps.
- Prefer a short example that demonstrates the convention over a catalog of speculative cases.
- Update docs when a change alters setup, user-visible behavior, project decisions, or a workflow's verification criteria.
