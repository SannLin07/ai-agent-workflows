# Git rules

- Keep commits focused and describe the intent with an imperative summary.
- Use a short-lived branch when work needs isolation, collaboration, or review; a small personal change may be committed directly when project policy allows it.
- Before committing, inspect the changed-file list and diff for unrelated edits, secrets, generated artifacts, and accidental deletions.
- Do not rewrite shared history or force-push unless the user explicitly requests it and the target is understood.
- Use pull requests when review or a durable discussion is useful. Keep the change and review checklist proportional to its risk.
- Tag releases and record user-visible changes when the project distributes versioned artifacts.
